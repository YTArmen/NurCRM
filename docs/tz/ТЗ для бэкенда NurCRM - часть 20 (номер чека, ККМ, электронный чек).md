# ТЗ для бэкенда NurCRM — часть 20: сквозной номер чека, ККМ, электронный чек

_12.10.2026. Источник — анализ конкурентов и запрос владельца «ККМ ЭСФ тоже в дизайн добавь», «сделай их дизайн». Макеты — блок «ККМ и ЭСФ» (Ф1–Ф3, Ф5–Ф6), «Оплата — терминал, QR, электронный чек» (Б3, Б6). Функция в конструкторе — `fiscal_kkm` (часть 19)._

## 1. Зачем

В Кыргызстане расчёты с населением — и товары, и услуги — проводятся через ККМ с выдачей бумажного и/или электронного чека (Порядок ККМ, ПКМ КР от 08.04.2022 № 193). Без ККМ можно работать по патенту. Плательщики единого налога применяют ККМ обязательно. Сейчас касса NurMarket фискальных чеков не выдаёт, поэтому магазины на едином налоге держат рядом вторую программу или приложение банка.

**До разработки уточнить у оператора (eKassa или MKassa) и по ПКМ № 193:** точный список реквизитов чека, API оператора, сколько времени можно хранить чек без отправки, правила чека возврата, предоплаты и залога за прокат.

## 2. Сквозной номер чека (нужен до ККМ)

Сейчас постоянного номера нет: сайт и касса нумеруют по месту в списке, номер старого чека растёт с каждой продажей (AI_HANDOFF, раздел 6).

Нужно поле продажи `number` — целое, сквозное по компании, **не меняется никогда**, выдаётся сервером при `checkout`.
- Отложенная или офлайн-продажа получает номер при приходе на сервер; до этого касса показывает «Чек · ждёт номера» и временный `local_number`.
- `GET api/main/pos/sales/?number=482` — поиск по номеру (возврат, привязка платежа банка, часть 21).
- Отображение — `000482`, шесть знаков с ведущими нулями.

## 3. Смешанная оплата — хранить разбивку

Сейчас при смешанной оплате сервер пишет `cash_received=0` и одну строку `mixed`. Для фискального чека и Z-отчёта нужна разбивка.

`payments: [{method: cash|card|qr|bonus|gift_card|credit, amount, bank?, reference?}]`

Сумма `payments` равна итогу чека. В Z-отчёте и сменах считать по разбивке.

```
CompanyTax

  vat_payer             — bool
  vat_rate              — 12
  sales_tax_rates       — [{method: cash|cashless, rate}]   — НсП, ставки задаёт владелец

FiscalDevice (одна на кассу)
  id, cashbox_id, branch_id
  provider              — ekassa | mkassa | okassa | megakassa | newcas | hardware
```

Для `patent` ККМ не используется: чек обычный, без отправки.

## 5. Фискализация — где она происходит

**Основной путь: облачная ККМ, фискализует сервер NurCRM.** Касса не хранит ключи оператора.

1. Касса делает `checkout` как сейчас, плюс `fiscal: true`.
2. Сервер создаёт продажу, получает `number` и отправляет чек оператору (eKassa или MKassa).
3. Ответ кассе: продажа + `fiscal: {status: registered, fd, fpd, shift_no, receipt_no, qr_url, ofd}`.
4. Касса печатает фискальный чек (Ф3) и показывает окно «Чек зарегистрирован в налоговой» (Ф2).

Если оператор не ответил за 5 секунд:
- продажа сохраняется, `fiscal.status = queued`;
- касса печатает чек с пометкой «ФД будет в электронном чеке» (Ф2, «Нет связи с налоговой»);
- сервер повторяет отправку (через 1, 5, 15 минут, потом каждый час);
- после регистрации — пуш кассе и обновление электронного чека.

**Касса без интернета.** Продажа идёт в локальную очередь (уже есть `OfflinePendingSalesStore`) с `client_uuid` и временем продажи. При связи — `checkout` с `sold_at` и `client_uuid`, дальше как выше. Повтор с тем же `client_uuid` не создаёт вторую продажу.

**Аппаратная ККМ (`hardware`).** Чек фискализует принтер на кассе. Касса присылает `fiscal` с реквизитами, полученными от принтера; сервер их только хранит.

## 6. Возврат

Чек возврата ссылается на исходный: `return_of_sale_id`, `return_of_fd`. Сервер регистрирует у оператора чек «возврат прихода». Частичный возврат — по строкам. Возврат денег на карту и QR — часть 21.

## 7. Смена и Z-отчёт

- открытие и закрытие смены отправляются оператору (у облачной ККМ — сервер, у аппаратной — касса);
- `GET api/main/fiscal/shift/{shift_id}/reconcile/` → `{sales_count, fiscal_registered, queued, failed, totals_by_method, vat, sales_tax}` — блок «Сверка с налоговой» в окне Z-отчёта (Ф2);
- закрыть смену при `queued > 0` можно: в отчёте предупреждение и список чеков.

## 8. Электронный чек

```
EReceipt
  sale_id, token (случайный, 22 символа), created_at
  channels_sent — [{channel: whatsapp|telegram|sms, to, at, status}]
  rating        — 1..5, comment   (оценка покупки, Б6)
```

- после продажи, если у чека есть клиент с телефоном или кассир ввёл номер и `send_e_receipt` включён, — сервер отправляет ссылку `https://check.nurcrm.kg/{token}` в WhatsApp (механизм напоминаний о долге) или в Telegram-бот, если клиент к нему привязан;
- `GET public/e-receipt/{token}/` → данные страницы Б6 без входа: магазин, номер, время, строки, итог, способ оплаты, `fd/fpd`, QR проверки, начисленные бонусы и баланс (часть 22), ссылка PDF;
- `POST public/e-receipt/{token}/rating/ {rating, comment}`;
- `GET public/e-receipt/{token}.pdf`.

## 9. API

```
GET  api/main/fiscal/settings/             CompanyTax
PUT  api/main/fiscal/settings/
GET  api/main/fiscal/devices/              список ККМ касс со статусом и очередью (Ф5, Ф6)
POST api/main/fiscal/devices/              подключить {cashbox_id, provider, reg_number, fiscal_module, credentials}
POST api/main/fiscal/devices/{id}/test/    пробный чек на 0 сом или тест связи
POST api/main/fiscal/devices/{id}/retry/   «Отправить сейчас»
GET  api/main/fiscal/queue/?cashbox_id=    чеки без ФД
GET  api/main/fiscal/z-reports/?date=      Z-отчёты всех касс (Ф5, Excel)
POST api/main/pos/sales/{id}/checkout/     + поля fiscal, client_uuid, sold_at, payments[]
POST api/main/pos/sales/{id}/e-receipt/    {phone|telegram_chat}  — отправить ещё раз
```

## 10. Права

`fiscal_kkm.settings` — владелец и админ. `fiscal_kkm.z_report` — кассир своей кассы.

## 11. Приёмка

1. Продажа на 650 сом, eKassa на тесте → `fiscal.status = registered`, у продажи `number` и `fd`; электронный чек открывается по ссылке.
2. Отключить сеть оператора → продажа проходит, `queued`; после восстановления — `registered` без участия кассира, номер чека не меняется.
3. Касса без интернета продаёт 3 чека → при связи 3 продажи, без дублей (`client_uuid`), время — фактическое.
4. Возврат 1 строки → чек возврата со ссылкой на исходный ФД; Z-отчёт сходится.
5. Смешанная оплата 400 наличными + 250 картой → в чеке и в Z-отчёте две строки.
6. Магазин на патенте (`patent`) → касса работает как сейчас, без запросов к оператору.
