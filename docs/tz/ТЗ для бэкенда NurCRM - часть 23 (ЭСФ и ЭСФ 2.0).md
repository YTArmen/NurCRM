# ТЗ для бэкенда NurCRM — часть 23: ЭСФ и ЭСФ 2.0

_12.10.2026. Источник — запрос владельца «ККМ ЭСФ тоже в дизайн добавь». Макеты — блок «ККМ и ЭСФ» (Ф4, Ф5, Ф6). Функция в конструкторе — `esf`, требует `fiscal_kkm` (часть 19)._

## 1. Что требует закон (кратко, сверить перед разработкой)

- ЭСФ оформляет продавец при продаже товаров, работ и услуг; покупатель подтверждает онлайн. Не обязаны, в частности: упрощённая система с доходом до 15 млн сом в год, патентщики, ИП на едином налоге, которые работают только с физлицами (разъяснение ГНС, октябрь 2025).
- **ЭСФ 2.0** — пилот с 01.09.2026 на 6 месяцев (распоряжение Кабмина № 705-т). Прослеживаемость товаров из перечня ЕЭК: сначала нефтепродукты, холодильники, морозильники, стиральные машины, телевизоры. Виртуальные остатки в системе должны совпадать с фактическими; срок сверки, по сообщениям прессы, — до 01.10.2026. Обязательность по категориям и детали — по официальным документам ГНС.
- ЭТТН для большинства товаров предлагается отменить (функции переходят в ЭСФ 2.0). В этой части ЭТТН не делаем.

**Нужен доступ к API или шлюзу ГНС для ЭСФ.** Если прямого API нет — интеграция через сертифицированного оператора. Выбор за NurCRM.

## 2. Для кого функция

- магазины, продающие юрлицам (опт, B2B) → исходящий ЭСФ;
- любой магазин, которому поставщик выставляет ЭСФ → входящий ЭСФ сразу становится приёмкой (главная экономия времени);
- продавцы техники из перечня прослеживаемости → сверка остатков ЭСФ 2.0.

## 3. Модель

```
EsfDocument
  id, company_id, direction — outgoing | incoming
  number_gns, status — draft | sent | confirmed | rejected | canceled | awaiting_receiving
  counterparty — {inn, name, vat_payer}
  payment_form — cash | cashless | barter | free         (четыре формы оплаты ЭСФ 2.0)
  delivery_date, contract — {number, date}
  lines — [{product_id?, name, gked_code?, tnved_code?, unit, qty, price, vat_rate, vat_amount, sum, traceable: bool}]
  totals — {sum, vat}
  sale_id? (исходящий), receiving_id? (входящий → приёмка)
  reject_reason, created_at, sent_at, confirmed_at, deadline_confirm

TraceableBalance (ЭСФ 2.0)
  product_id, gns_item_code, qty_ours, qty_gns, diff, checked_at
```

## 4. Исходящий ЭСФ (Ф4, «Выписать ЭСФ»)

1. Кассир или админ вводит ИНН → `GET api/main/esf/counterparty/?inn=` → название и признак плательщика НДС из базы ГНС.
2. `POST api/main/esf/ {sale_id | lines, counterparty, payment_form, delivery_date, contract}` → черновик; коды ГКЭД подставляются из товаров (поле товара `gked_code`, заполняется один раз).
3. `POST api/main/esf/{id}/send/` → в ГНС; статус обновляется по ответу и опросу.
4. Отклонён → `reject_reason` на кассе, телефоне и в вебе (Ф5, Ф6: «причина: неверный ИНН»).

## 5. Входящий ЭСФ → приёмка (Ф4)

1. Сервер раз в 15 минут забирает входящие ЭСФ по ИНН компании.
2. Строки сопоставляются с товарами: по `tnved/gked` и штрихкоду, потом по названию (нечёткое сравнение, порог задаёт NurCRM). Результат — `matched` / `new` по каждой строке.
3. `POST api/main/esf/{id}/to-receiving/ {lines:[{line_id, product_id | create:{…}}], update_cost: true}` → черновик приёмки (как существующая приёмка), закупочные цены — из ЭСФ.
4. После проведения приёмки, если отмечено «Подтвердить ЭСФ после приёмки», — подтверждение в ГНС.
5. «Отклонить» — с причиной.

## 6. Сверка ЭСФ 2.0 (Ф4, «Сверка с ЭСФ 2.0»)

- товар отмечается `traceable` (вручную или по коду ТН ВЭД из перечня);
- `GET api/main/esf/traceable/reconcile/` → `[{product, qty_ours, qty_gns, diff}]`;
- при расхождении — кандидаты причин: продажи этого товара без ЭСФ, списания без документа;
- кнопки «Найти продажи» и «Оформить списание» готовят документ, отправляет человек.

## 7. API

```
GET  api/main/esf/?direction=&status=&page=
GET  api/main/esf/{id}/
POST api/main/esf/                      черновик
POST api/main/esf/{id}/send/
POST api/main/esf/{id}/cancel/
POST api/main/esf/{id}/confirm/         входящий — подтвердить
POST api/main/esf/{id}/reject/          {reason}
POST api/main/esf/{id}/to-receiving/
GET  api/main/esf/counterparty/?inn=
GET  api/main/esf/summary/              {incoming_waiting, outgoing_month, rejected}
GET  api/main/esf/traceable/reconcile/
PUT  api/main/products/{id}/            + gked_code, tnved_code, traceable
```

## 8. Уведомления

Новый входящий ЭСФ, отклонённый исходящий, срок подтверждения через 1 день — в телефон владельца и в Telegram-бот (Ф6).

## 9. Права

`esf.create`, `esf.send`, `esf.confirm` — админ. Кассир может создать черновик исходящего при продаже юрлицу, если есть право `esf.create`.

## 10. Приёмка

1. Продажа юрлицу → ЭСФ со строками и НДС 12 % → `sent` → `confirmed` (на тестовом контуре ГНС).
2. Входящий ЭСФ из 5 строк: 4 найдены, 1 новая → «Создать товар» → приёмка проведена, остатки выросли, цены закупки обновлены.
3. Неверный ИНН → `rejected` с причиной на всех устройствах.
4. Товар `traceable`: у нас 7, в ГНС 9 → расхождение −2 и кандидаты причин.
