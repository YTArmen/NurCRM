## 2. Как выкатывать

1. `git fetch && git checkout feature/tz-17-28-backend` (ветка пока только локально у Умара — отдать Беке через PR или патч).
2. **Миграции.** В `.gitignore` стоит `**/migrations/*.py` — миграции `main` живут только на сервере. Моя `possync/0001_initial` добавлена исключением в `.gitignore` (как у `ekassa` и `onec`) и зависит от `main.0144_telegram_bot_part15_voice_actions`. На сервере миграции `main` новее — зависимость при этом не мешает. Если `main.0144` на сервере называется иначе, поправить одну строку `dependencies`.
3. Миграция `possync.0001` **не атомарная** (`atomic = False`) — индексы создаются `CONCURRENTLY`. Запускать в обычное время можно, таблицы не блокируются. На 50 000 продаж это секунды.
4. Резервная копия файлов перед правкой, `kill -HUP` мастеру gunicorn — как обычно.
5. Касса и телефон могут переходить на новые адреса постепенно: старые не менялись (кроме формата ошибок — см. п. 4).

## 6. Замечания по совместимости

- Формат ошибок: ключи полей сохранены, добавлены `code`, `detail`, `fields`. Веб-админка маркета читает `detail`/`non_field_errors` (`src/lib/api.ts`) — ей станет только проще. Если где-то фронт перебирает **все** ключи ответа как поля формы — нужно пропускать `code`, `detail`, `fields`.
- Повтор `pos/checkout/` с тем же ключом: как раньше 200 + `replayed: true`; добавился только `409 idempotency_conflict` при другом составе.
- `GZipMiddleware` сжимает только при `Accept-Encoding: gzip` — старые клиенты без заголовка ничего не заметят.
