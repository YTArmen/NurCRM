## Правила ТЗ
- Всё только добавлением: старые ответы API кассы не ломать. Поведение, которое меняет цену/количество/отказ в существующем запросе — только под флагом: `from core.api_compat import is_hardware_strict, is_strict, is_new_client` (хозмаг — `is_hardware_strict(request, company)`).
- Ключ повтора: `apps/integrations/idempotency.py` (декоратор `idempotent`). Ошибки: `core/exceptions.py` (`ApiError`) — посмотри, как используют в соседнем коде (grep "ApiError(").
- Права: смотри, как сделано в соседних вьюхах (owner-like: `apps/utils.py` `_is_owner_like`, флаги `can_view_*` у пользователя).
- Компания пользователя: `request.user.owned_company or request.user.company`; филиал — посмотри, как соседние вьюхи берут филиал.
- Никаких внешних сетевых вызовов в тестах — мокай (`unittest.mock.patch`). Никаких ключей/токенов в коде. Новые библиотеки НЕ ставить — если нужна, напиши в отчёте.
